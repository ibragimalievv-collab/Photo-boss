# График одним текстом

График → «+» → «Вставить график одним текстом». Выберите сотрудника один раз,
вставьте строки `ДД.ММ.ГГГГ–ДД.ММ.ГГГГ — менеджер/фотограф/выходные`, нажмите
«Проверить график», затем «Применить весь график». Поддерживаются 1–31 последовательный
день и переход между месяцами/годами. Пропуски, пересечения, неверные даты и несовпадение
контрольных итогов отклоняются до изменения базы. Вставляйте сам график, не техническое задание.

Отель и часы переиспользуются только из однозначного сохранённого расписания; единственная
привязка к действующему отелю может подтвердить отель, но не часы. Недостающие значения
запрашиваются в одной общей форме. Прямой выбор общих параметров имеет приоритет.

Назначение роли на день не меняет `user_roles`. Дневной план хранится в `settings`
с префиксом `schedule.day:`. Выходной — отдельная запись, не отсутствие данных.
Фактические смены/продажи/выплаты не переписываются. Прошедшие, начавшиеся по времени,
подтверждённые/ожидающие проверки смены сохраняются; их новый план помечается отдельно,
если его часы не совпадают с фактом. Изменяемые будущие смены отменяются без удаления истории.

POST `/api/miniapp/schedule/text/preview`, `/apply`, `/verify` используют существующую
аутентификацию и повторную серверную проверку OWNER/ADMIN и отелей. Применение блокирует
сотрудника и редактора в стабильном порядке; запись всего периода, аудита и квитанции
идемпотентности выполняется одной транзакцией. Изменение данных после предварительной
проверки даёт 409. Сеть/повторный клик не создают дубликаты. После commit сервер и клиент
независимо перечитывают сохранённые даты. Позднее ручное редактирование имеет приоритет;
старую квитанцию нельзя использовать для молчаливого возврата старого графика.

## Однократное применение поручения владельца при выпуске

Только для production-сервиса, переменная `PHOTO_BOSS_SCHEDULE_TEXT_REQUEST` содержит
JSON с `requestKey` (16–64 символа), `text`, ровно одним из `userId`/`employeeName`,
необязательным `defaults: {hotelId, start, end}`. Без переменной ничего не применяется.
При имени требуется единственное точное совпадение имени/слова имени; похожие имена
выводятся как кандидаты, но не выбираются. Нужен активный OWNER из настроенных admin_ids.
Применяется тот же проверенный сервис, не отдельная SQL-правка. Неоднозначность или
отсутствие настроек дают `needs_confirmation` в журнале; ни один день не изменяется.
`VERIFIED` выводится только после повторного чтения всех дней. После выполнения переменную
следует убрать/обнулить. Повторный запуск с прежним ключом только проверяет прежний результат.

## Проверки

`pytest -q tests/test_schedule_text_import.py tests/test_schedule_batch.py tests/test_miniapp_release.py`

`PYTHONPATH=. python tests/schedule_text_browser_check.py` — настоящий интерфейс и API,
ширины 1366 и 320, потерянный ответ после commit, повтор и двойной клик, выходной в календаре.

`PYTHONPATH=. UPDATE_POSTGRES_TEST_URL=... python tests/schedule_text_postgres_check.py` —
только изолированная тестовая PostgreSQL: уникальная временная схема, rollback и два
параллельных одинаковых запроса. Тест никогда не должен запускаться на рабочей базе.
