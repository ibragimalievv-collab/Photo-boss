# Проверка и обновление Photo Boss

Проверяйте по одному сценарию и фиксируйте время, роль, номер записи и последний
успешный шаг. Не создавайте продажу повторно для проверки зависшей отправки.
Не очищайте данные браузера, пока исходные файлы остаются в локальной очереди.

## Приёмка на рабочем устройстве

| Шаг | Действия | Признак успешной проверки |
| --- | --- | --- |
| Вход и права | Войти владельцем, администратором, менеджером и фотографом; открыть чужую запись прямой ссылкой | Фотограф видит назначенные съёмки, менеджер свои записи, администратор свои отели; запрещённые запросы отвергает сервер |
| Запись | Создать запись, назначить фотографа, изменить время, перенести и отменить | Изменения совпадают в вебе и боте, причины и история сохраняются |
| Смена | Разрешить геолокацию и камеру, снять контрольное фото, начать и завершить смену | Показан фактический результат; повторная отправка не создаёт вторую отметку |
| Напоминания о записях | На подтверждённой смене дождаться заданного интервала без новых записей; открыть главный экран владельцем, администратором и менеджером | В Telegram и приложении названы отель и менеджеры на смене; владелец видит все активные отели без записей сегодня, администратор только свои, менеджер только свой отель. Повтор не приходит чаще выбранного интервала; перевод между отелями остаётся решением администратора |
| Этапы съёмки | Забрать назначенную съёмку → начать → завершить → готова к продаже | Каждая кнопка меняет один допустимый этап; после обновления страницы этап сохраняется |
| Фотографии | Загрузить JPEG/PNG/WebP и папку; отключить сеть посреди передачи, закрыть и снова открыть приложение | Исходные файлы остаются в очереди; после синхронизации нет дублей; статус `STORED` подтверждает сохранение на Диске |
| Продажа и чек | Оформить одну продажу; прервать передачу чека и повторить синхронизацию | Сначала сохраняется чек, затем количество, выбранные кадры и продажа; сумма и количество соответствуют серверным правилам; продажа одна |
| Исправление фото | В допродаже выбрать ранее купленный кадр, затем заменить отклонённый файл новым | Появляется понятная ошибка и замена файла; существующая очередь продолжается без новой продажи |
| Догрузка съёмки | После продажи открыть ту же съёмку и догрузить оригиналы | Кнопка загрузки доступна до закрытия полной загрузки; счётчики отражают фактические файлы |
| Чек и деньги | Открыть фото чека, результат распознавания и сверку суммы | Сохранение, распознавание и подтверждение оплаты показаны отдельно; поступление подтверждает владелец после выписки |
| Академия | Отправить пять кадров, дождаться решения, заменить только отмеченные кадры | Видны состояние и причина сбоя; повтор не затирает новую проверку, сохраняются остальные кадры и история |
| Гость | Открыть QR без Telegram, выбрать и скачать разрешённые фото | Доступны только отправленные гостю фотографии; чужие оригиналы и служебные данные недоступны |
| Отчёты | Сверить сумму продажи, кассу, комиссию и зарплату на одной тестовой записи | Итоги совпадают; сотрудник не видит чужие выплаты |

Чаты, вложения, непрочитанные сообщения и звонки проверяются двумя отдельными
аккаунтами и устройствами. Для звонков через разные мобильные сети отдельно
проверяется TURN; локальный браузерный тест не подтверждает такую связь.

## Выпуск исправлений

1. Воспроизвести конкретную ошибку и добавить проверку, которая падает на старом коде.
2. Исправить причину; сохранить исходные файлы, ключи операций и ограничения доступа.
3. Запустить Python-регрессии, клиентские проверки и браузерные сценарии восстановления.
4. Дождаться всех проверок pull request, включая отдельную PostgreSQL и миграции.
5. Объединить проверенный коммит, дождаться `live` в Render и проверить `/health`.
6. Сверить версию, подключение PostgreSQL и Диска; проверить новые ошибки в журнале.
7. Повторить приёмку на исходном устройстве с сохранённой очередью пользователя.

Браузерные автотесты используют искусственные записи и имитации ИИ/хранилища.
Они проверяют логику приложения, но не заменяют отправку реальных файлов с
конкретного телефона и проверку внешних сервисов. Успешное распознавание чека
не подтверждает поступление денег.

## Контроль инфраструктуры

У веб-сервиса Render должен быть задан `Health Check Path: /health`. Эндпоинт
проверяет готовность приложения и запрос `SELECT 1` к PostgreSQL; один открытый
TCP-порт не доказывает работу базы. После смены тарифа БД проверяйте не только
статус базы `available`, но и HTTP-ответ приложения, восстановление фоновых
задач и свежие журналы. Не открывайте внешний доступ к PostgreSQL ради проверки.
