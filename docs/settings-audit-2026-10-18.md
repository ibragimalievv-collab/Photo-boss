## Исправленная ошибка доступа в 3.29

Запоздалый ответ запроса владельца мог завершиться после начала переключения на другой аккаунт и попасть в экран или сохранённый снимок. Ошибка воспроизведена тестом до исправления.

Теперь переключение аккаунта меняет ревизию авторизации. Прежний запрос проверяет её до отправки, после ответа, чтения JSON/изображения, согласования поколения и чтения/сохранения офлайн-снимка. Устаревший запрос отклоняется; он не сбрасывает новую сессию своим поздним 401 и не возвращает предыдущие частные данные. Исходные операции и фотографии не удаляются.

## Слабые места настройки

1. **Нет рабочего TURN.** Нужен действующий relay и его доступы в Render (`CALLS_TURN_URLS` и общий секрет либо пара username/credential). После подключения проверить два настоящих устройства из разных сетей. Пустые или выдуманные доступы проблему не решают.
2. **База 1 ГБ без автоматического роста и HA.** Render сообщает PostgreSQL 16, доступна, Frankfurt, без read replica. Фактический занятый объём этой проверкой не получен: внешний SQL закрыт. Увеличение тарифа и резервный узел не включались автоматически.
3. **Нет подтверждённой независимой полной копии.** Ночной JSON-экспорт содержит сотрудников, гостей, брони и продажи; он не содержит всех таблиц, архива сброса и бинарных файлов. Нужны отдельный полный экспорт базы, копия медиа, защищённые настройки запуска и пробное восстановление на отдельном окружении. Код на GitHub не заменяет копию базы.
4. **Репозиторий Public.** Для ограничения дальнейшего чтения кода владелец может изменить видимость в GitHub → Settings → General → Danger Zone → Change repository visibility → Private. Затем проверить, что GitHub App Render имеет доступ к закрытому репозиторию, и выполнить проверочное развёртывание. Уже скачанные копии этим не удаляются.
5. **Нет геозон и стандарта формы.** Для реализации нужны точные точки/границы каждого отеля и утверждённое описание либо образец формы. Нельзя подставлять приблизительные координаты и автоматически штрафовать за неопределённый GPS или спорную фотографию.
6. **Нет закрытых-app push.** Для этой функции нужны отдельная реализация Web Push, защищённое хранение подписок, настройка ключей VAPID, согласие каждого устройства и тесты Android/iPhone/Mac. Telegram-уведомления не равны браузерным push.

## Нагрузка на момент проверки

По метрикам Render за 14:05–14:35 UTC процесс приложения использовал около 246–248 МБ из 2 ГиБ и примерно 0,4% одного CPU. PostgreSQL: примерно 60–79 МиБ из 256 МиБ, 4–6 активных соединений. Признаков текущей перегрузки по этим метрикам нет; объём свободного места базы ими не подтверждается. HTTP p95 не получен: ряд пустой.

## Как проверить после обновления

1. Завершить текущую отправку, закрыть и заново открыть Photo Boss. Не очищать данные браузера с неотправленными файлами.
2. Войти владельцем, открыть «Диск и галереи», нажать блок объёма Диска → «Проверить запись, чтение и файлы». Сверить текущий аккаунт и свежую дату результата.
3. Создать запись и пройти её этапы на отдельном тестовом окружении либо выполнить настоящую рабочую операцию с реальными данными; не создавать фиктивные продажи в рабочей кассе ради проверки.
4. Проверить загрузку с обрывом связи: исходные файлы остаются в очереди до подтверждения; повтор не увеличивает количество одинаковых кадров и не создаёт второй платёж.
5. Переключиться с владельца на сотрудника; касса, аудит и чужие записи не должны появляться. На медленной сети старый ответ должен отклониться.
6. Для звонков между разными сетями сначала настроить TURN. Для геозон сначала утвердить точки отелей и допустимую погрешность; для контроля формы — сам стандарт.

Аудит не означает отсутствие любых будущих ошибок. Таблица различает рабочую проверку, изолированные тесты и ещё не настроенные возможности.
