# Проверенные границы QR.API

Схемы просмотрены 28 октября 2026 года в отрисованной официальной документации:

- [Создание заказа](https://developers.sber.ru/docs/ru/sber-api/specifications/qr/plati-qr/order-create).
- [Запрос статуса](https://developers.sber.ru/docs/ru/sber-api/specifications/qr/plati-qr/status-request).
- [Адреса промышленного контура и scopes](https://developers.sber.ru/docs/ru/sber-api/scenarios/transfers/qr-payment/opisanie-servisov).

Для создания нужны выданные банком `member_id` и `id_qr`; для проверки — `tid`
и `partner_order_number`. `order_id` в запросе статуса необязателен: запрос по
номеру позволяет сверить неопределённый результат регистрации без повторного
создания. Идентификаторы из примеров документации использовать нельзя.

Ответ статуса не содержит суммы/валюты заказа на верхнем уровне. Доказательство
оплаты — операции `PAY`, их `operation_sum`, `operation_currency` и банковский
код результата. Операции возврата учитываются отдельно. `settlement_verified`
отличает проверенные операции от ожидаемых параметров неоплаченного заказа.

В актуальной схеме ответа `order_operation_params.items.required` явно включает
`operation_id`, `operation_date_time`, `rrn`, `operation_type`, `operation_sum`,
`operation_currency`, `auth_code`, `response_code`. У `rrn` и `auth_code`
задан непустой строковый шаблон; эти проверки взяты из схемы, а не из примера.
Дополнительный блок `sbp_operation_params` не заменяет обязательные поля
операций. Источник схемы — [ресурс официальной документации](https://media.sberdevices.ru/bsm-docs/0.958.1/docs/assets/js/e90ae122.4a779928.js),
загруженный страницей запроса статуса 28 октября 2026 года.

Адреса песочницы и значения кодов успеха требуют отдельного подтверждения Сбера.
Схема содержит условный пример `error_code`, поэтому клиент не подставляет
значение успеха по предположению. Общая песочница fintech и OAuth пользователя
не заменяют QR.API. Промышленный профиль зафиксирован по описанию сервиса;
песочница автоматически на него не переключается.
Профили с `/prod` запрещены для песочницы и при отдельной проверке OAuth,
чтобы тестовые ключи не отправлялись в промышленный контур.

`check_connection()` проверяет только OAuth. Он не создаёт заказ или чек.
`TEST_PAID` не подтверждает выручку. При неизвестном адресе, кодах или
идентификаторах клиент завершает проверку без банковского запроса.
