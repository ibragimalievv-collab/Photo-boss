# Photo Boss 3.47 — исправления и функциональный аудит

Дата: 26 октября 2026, Москва.

## Исправления выпуска

* Обед выбирает единственный отель из графика сотрудника. Если вариантов несколько,
  требуется явный выбор; выбранный вручную отель сохраняется при обновлении панели.
* После подтверждённой синхронизации начала смены обновляется доступность обеда.
  Локальная очередь сама по себе не считается сохранённой серверной отметкой.
* При проверке смены руководителем сохраняются секунды подтверждённого времени.
* Убран прежний предел 8 МиБ на оригинал в практике Академии. Загрузка крупных
  JPEG передаётся потоком, исходный файл и EXIF сохраняются. Проверяются размер
  и контрольные суммы сохранённого оригинала. Для ИИ создаётся отдельная копия
  до 2048 пикселей и 1,5 МиБ. Такая копия не подтверждает резкость оригинала 1:1.
* Технический предел Академии по умолчанию — 256 МиБ на кадр. Настройка
  `PHOTO_BOSS_ACADEMY_MAX_IMAGE_MB` допускает значения 32–1024. Текущий предел
  возвращается сервером в задании и показывается в интерфейсе. Бесконечный размер
  файлов или хранение без квоты не обещаются. PNG/WebP преобразуются в JPEG;
  HEIC/HEIF необходимо предварительно экспортировать в JPEG.
* При удалении назначенной записи в корзину фотограф получает уведомление об
  отмене в той же транзакции. Повтор не создаёт второе уведомление.
* Задержавшиеся ответы платёжного QR, создания счёта и проверки банка не
  отображаются в другой съёмке после переключения. При последовательном выборе
  нескольких QR отображается последний выбранный счёт. Повтор после ошибки
  банка сохраняет исходные параметры и ключ регистрации.
* Сохранение тарифов и альбомов обновляет строки, кнопки повторного редактирования
  и варианты в форме продажи. Поля выбранных файлов и чека остаются теми же;
  согласованная цена существующего черновика не заменяется новой.
* Поздний ответ загрузки одной съёмки не меняет выбранную другую съёмку, форму
  или открытый раздел. Перед отправкой проверяются исходная съёмка, аккаунт
  и принадлежность формы; смена экрана не переносит чужие кадры в новую продажу.
* После подтверждённого отказа 409 из-за смены папки Диска можно явно заменить
  отклонённый кадр выбранным из новой папки. Сохраняются исходный черновик и ключ
  операции; принятые кадры, чек и количество не переписываются. Неопределённые
  ответы 503 и операции другого черновика этим действием заменить нельзя.
* Исправляется порядок блокировок фоновых уведомлений и безопасный повтор
  транзакции PostgreSQL после deadlock/serialization failure. Повтор выполняется
  с новой транзакцией; внешние отправки Telegram и резервного экспорта не
  повторяются этим механизмом.
* Обновлён кеш приложения для получения новых модулей установленными клиентами.

## Выявленные ограничения production

По публичному `/health` до выпуска 3.47:

* PostgreSQL отвечает; версия приложения 3.46, commit `396c70cc6998`.
* Внутриприложные уведомления и push настроены.
* `attendance.gpsRequired=true`, `geofenceRequired=false`: нужны координаты
  устройства; расстояние до отеля сейчас не является обязательной проверкой.
* `payments.configured=false`: банковская интеграция не подключена.
* `calls.relayConfigured=false`: TURN-сервер не настроен; медиасвязь между
  ограничивающими мобильными сетями не гарантируется.
* Флаги успешного чтения/записи Яндекс.Диска относятся к стартовой проверке
  25.10.2026 05:08:53 UTC. Это не свежий тест чтения/записи 26 октября.
* Прямой read-only запрос через Render MCP к production-БД недоступен из-за
  закрытого внешнего доступа. Сетевые ограничения БД не ослаблялись.

Автоматические проверки не создают реальные смены, штрафы или продажи сотрудников.
Полный цикл на исходном рабочем телефоне и отдельных реальных ролях не считается
подтверждённым только на основании HTTP 200, зелёных тестов или статуса `live`.

## Wfolio

Пользователь выбрал совместное использование Wfolio и Яндекс.Диска: оригиналы
и автоматическая проверка остаются в Photo Boss через Яндекс.Диск, Wfolio
планируется использовать для клиентских галерей и отбора.

Подтверждённая официальная интеграция — совместный тариф Яндекс 360 + Wfolio:
оригиналы загружаются и управляются на Яндекс.Диске, галерея Wfolio автоматически
отражает изменения связанной папки. Галерея поддерживает защитный ключ ссылки,
пароль и водяной знак. Photo Boss можно дополнить ссылкой на такую галерею.

Публичный API для полного управления хранилищем Wfolio, программного создания
галерей и получения оригиналов не подтверждён. Полная замена Яндекс.Диска требует
официальных API-условий и доступа Wfolio. В этом выпуске Wfolio не подключается,
данные не переносятся и подписки не покупаются.

Источники, проверенные 26.10.2026:

* <https://docs.wfolio.pro/billing/yandex>
* <https://docs.wfolio.pro/drive/projects/protect>
* <https://docs.wfolio.pro/llms.txt>

Точный состав автоматических проверок и результаты данного коммита доступны
в GitHub Actions соответствующего pull request. Известные условия проверки
реального устройства перечислены в `docs/testing-and-release.md`.
