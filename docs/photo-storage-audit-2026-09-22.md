# Photo Boss: хранение и обработка фотографий

Проверен main `2c9ac7a2`, 22 сентября 2026. Просмотрены открытые PR #2, #4, #13 и #31; #31 пересекается с проверкой текущих ролей в `workflow.py` и исправлением устаревшего теста входа. Изменения выполнены в отдельной ветке, production не изменён.

## Матрица исходного состояния и изменений

| Требование | В main до изменения | Доказательство и результат |
|---|---|---|
| API Яндекс.Диска, серверный токен | Уже реализовано | `app/yandex_disk.py`: OAuth только на сервере; namespace `app:/PhotoBoss`; нет вызовов publish. `/health` рабочего сервиса подтверждает configured/connected/writeVerified. |
| Съёмка, количество, состояние каждого файла | Частично | `photo_storage` имел серверные статусы, Mini App показывал только синхронизацию операции. `app/workflow.py` и `app/webapp/js/workflow.js` теперь показывают съёмку, номера кадров, число сохранённых, ожидание/ошибку и версии обработки. Имя выбранного файла сохраняется в локальной очереди и связывается с серверным номером кадра. |
| Пакет, плохая сеть, повторное открытие | Частично | Существующий IndexedDB outbox сохраняет пакет атомарно и повторяет операции с тем же ключом. Сохранено это поведение, добавлена проверка пакетной загрузки после закрытия страницы без сети. |
| Повтор только неудачных сохранений | Отсутствует в Mini App | `shoot_retry` сбрасывает только FAILED своей съёмки. STORED не трогает; доступ повторно проверяется сервером. Доступно и после закрытия полной загрузки. |
| Зависшие попытки | Частично | Последняя UPLOADING с attempts=5 зависала навсегда. После 10 минут переводится в FAILED. Старый исполнитель не может завершить новую попытку: проверяются номер и время захвата. Между автоматическими повторами ошибок есть пауза 60 секунд. |
| Подтверждение сохранения | Частично | Ранее проверялось лишь получение метаданных после PUT. Теперь `validate_saved` требует type=file, совпадение размера и SHA256 или MD5. Только затем возможен STORED. «Принято сервером» отделено от «Сохранено на Диске». |
| Дубли | Частично | Сохранены ключи OperationRequest и SHA256 в пределах съёмки. Мобильный сценарий из трёх файлов с одним дублем создаёт ровно два Photo/PhotoStorage. Обработанные версии не увеличивают количество оригинальных кадров. |
| Заполненное хранилище | Частично | HTTP 507 остаётся ошибкой; показывается просьба освободить место. Тест проверяет успешный выборочный повтор после освобождения. |
| Права доступа, токены, отсутствие публичных ссылок | Частично | Назначение теперь проверяется вместе с текущей ролью фотографа. Новая выдача оригиналов/копий проверяет принадлежность кадра съёмке и доступ актёра. Ответы no-store; URL Диска и токены клиенту не передаются. Менеджер не может получить изображение через новый маршрут. |
| AI-обработка, отдельная от Академии | Отсутствует | Новый `app/photo_edits.py`, таблица `photo_edits`, миграция `012_photo_edits.sql`. Общий транспорт структурированного AI-ответа переиспользуется; учебный разбор не выдаётся за обработку. |
| Оригиналы, копии, сравнение, повтор, отмена | Отсутствует как этап обработки | Оригинал в PhotoStorage неизменен. Каждый запуск — версия PhotoEdit; JPEG-копия в `shootings/{id}/processed`. Сравнение внутри Mini App через авторизованные запросы; повтор FAILED, отмена любой версии. Поздний исполнитель не публикует отменённую версию. Хеш в имени копии исключает перезапись результата другой попыткой. |
| Сохранение внешности | Отсутствует обработка | AI выбирает только ограниченные числовые параметры: экспозиция, контраст, насыщенность, красный/синий баланс. Pillow применяет глобальную коррекцию без генерации, изменения геометрии, пластики или ретуши лица. EXIF-ориентация применяется; размеры кадра сохраняются с учётом ориентации. |
| Работа без AI | Отсутствует ручной этап | Ручные параметры используют тот же безопасный рендер. Отсутствие ключа отклоняет только AI-операцию; сбой AI переводит задачу в FAILED и не мешает следующей ручной задаче. |

## Границы приёмки

- Новые сценарии проверены с тестовыми Telegram/Яндекс.Диском/AI, а не на фотографиях гостей. Не выполнены реальные Android/iPhone, рабочий вызов AI и испытание ограничений рабочего Диска.
- PostgreSQL-конкурентность и миграцию необходимо проверить перед выпуском; локальные тесты используют SQLite. Таблица добавляется штатным create_all; отдельный SQL приложен для управляемого выпуска.
- Оригиналы Mini App по существующему маршруту сначала сохраняются как Telegram-документы, затем очередь переносит их на Диск. Локальный blob удаляется после серверного приёма. Это не новый прямой клиентский доступ к Диску; серверный приём явно отличается от завершения сохранения.
- Поддержаны JPEG/PNG/WebP, исходные файлы до 20 МБ; RAW/HEIC и загрузка частями одного файла не добавлены. Повтор отправляет целиком только неуспешный файл. Локальная очередь переживает закрытие, но не очистку данных приложения пользователем.
- Отмена скрывает обработанную версию и запрещает её выдачу; её байты могут оставаться на Диске. Оригиналы при отмене не удаляются.
- Коррекция глобальная: она не восстанавливает пересвеченные детали и не заменяет профессиональную локальную ретушь. Живое качество AI-подбора требует оценки на согласованных эталонных фотографиях.
- Ни платный сервис, ни новый ключ этим PR не подключаются. Используется существующий серверный OpenAI transport при наличии ключа; пользователь запускает AI явно.
