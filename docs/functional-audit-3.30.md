# Photo Boss: проверка функций и исправления 3.30

Проверка начата 18 октября 2026 года после повторной жалобы на незавершённые продажи в версии 3.29. Реальные продажи, суммы и количество кадров не исправляются догадкой. Тестовые продажи и уведомления выполняются на изолированных данных.

## Подтверждённые причины ошибок

| Сбой | Причина | Исправление |
| --- | --- | --- |
| Продажа остановилась до первого фото, повтор ничего не меняет | После завершения полной загрузки фактический размер съёмки отличается от старого общего количества. Сервер отклоняет `sale_counts`, а форма блокирует исправление | Для точного отказа из-за общего количества разрешено исправить только это поле, пока последующие операции ещё не выполнялись. Сохраняются исходный ключ, чек, фотографии и указанное проданное количество |
| Повторная тестовая продажа не переходит к фото | Уже использованный чек отклонён сервером, а интерфейс не предлагал заменить его | После точного окончательного отказа о повторном чеке разрешено заменить файл в исходной операции. При неопределённом результате отправки подмена файла запрещена |
| В Академии выбор следующего фото пропадает | Во время отправки одного кадра другие поля оставались активны, обработчик молча игнорировал их | Все поля временно блокируются; отображается состояние отправки |
| После повторного открытия практики прогресс откатывается | Запоздалый ответ предыдущего окна заменял более свежие данные | Ревизия окна и операции проверяется до показа ответа; старые результаты отклоняются |
| В практике остаются данные прежнего аккаунта | Диалог и URL фотографий не очищались сразу при смене пользователя | Сброс аккаунта закрывает практику, освобождает фотографии, очищает задание и останавливает опрос |
| JPEG из телефона или облака не принимается | Некоторые файловые менеджеры не передают MIME или указывают общий бинарный тип | Для таких случаев формат определяется по расширению, содержимое по-прежнему проверяет сервер. HEIC требует экспорта в JPEG; автоматическое изменение оригинала не выполняется |
| Администратор может изменить график другого отеля | На маршрутах графика отсутствовала проверка назначенных администратору отелей | Чтение, добавление, пакетное назначение и отмена смен проверяют отель объекта. Полный список сотрудников для назначения сохранён |
| Администратор видит чужие отметки и фотографии прихода/ухода | Проверялась роль, но не принадлежность рабочего дня отелю | Для администратора день определяется его неотменённым планом смен. Чужой, смешанный или неплановый день проверяет владелец |
| Фото галереи открывается после её закрытия | Запоздалый ответ изображения не сверял текущее окно | Закрытие, переход, сброс рабочих данных и смена аккаунта закрывают просмотр и освобождают URL фотографий |
| Новое уведомление не отправляется после большого числа недоступных получателей | Обработчик просматривал только первые 100 событий, в том числе ожидающих отложенного повтора | Очередь просматривается страницами до границы, зафиксированной в начале прохода; число попыток отправки остаётся ограниченным |

Прогресс продажи теперь отдельно показывает принятые кадры, копии файлов, ожидающие отправки фотографии и ошибки. Количество служебных операций больше не выдаётся за количество фотографий. Новые ответы сервера содержат число принятых кадров; старые сохранённые ответы поддерживаются.

## Что проверяется по функциям

| Раздел | Проверки | Граница проверки |
| --- | --- | --- |
| Вход и аккаунты | Telegram, пароль, неверный пароль, смена аккаунта, поздние ответы, закрытие приватных изображений | Браузер рабочего сайта без входа показывает экран авторизации. Ролевые сценарии проходят в изолированных браузерных тестах |
| Запись и этапы | Создание следующей записи, назначение фотографа, принятие и этапы, перенос/отмена/корзина, конфликты и доступ по отелю | Настоящие записи в рабочей базе автоматически не создаются ради проверки |
| График | Обе кнопки, полный тестовый список сотрудников, поиск, несколько дней/отелей, пересечения, отмена, права администратора | 108 сотрудников в браузерной проверке — тестовый набор |
| Продажа | Чек, количество, фото, завершение, повтор запроса, потеря ответа, исправление общего количества, замена отклонённого чека | Сервер не завершает продажу без требуемых выбранных фотографий; суммы не меняются автоматически |
| Академия | Пять фото, задержанный и потерянный ответ, пересъёмка, закрытие/повторное открытие, смена аккаунта, формат исходного JPEG | AI-ответы в автоматических сценариях тестовые; качество оценки реальных людей этим не доказывается |
| Диск и выдача | Запись/чтение и контрольная сумма, восстановление загрузки, два набора фото, QR и доступ гостя, приватный просмотр | Проверяется подключённый аккаунт Диска; все старые аккаунты этим не сканируются |
| Приход и уход | Онлайн/офлайн, камера/GPS, ручная проверка, отсутствие лишних штрафов, доступ по плану дня | Координаты не заменяют границы отелей; геозоны и распознавание формы ещё не настроены |
| Чаты и звонки | Диалоги, вложения, голос, непрочитанные, присутствие, камера/микрофон, тестовый TURN | На рабочем сервере TURN отсутствует; связь через любые сети не подтверждена |
| HR и команда | Роли, доступ владельца/администратора, карточки и базовые действия покрыты тестами | Живые кандидаты не получают тестовых сообщений и не переводятся между этапами |
| Уведомления | Повтор назначения, смена фотографа, недоступный Telegram, задержка повторов и очередь больше 100 событий | Уведомления идут через Telegram и внутри приложения; отдельные системные Web Push не добавлены |

## Наблюдения на рабочем сервере

Версия 3.29 была подтверждена по внешнему адресу и исходным файлам, выпуск 3.30 проверяется отдельно после развёртывания. В 18:57–18:59 МСК журнал показывает успешные ответы 200 на отправку медиа длительностью около 6–11 секунд. Это подтверждение отдельных отправок, а не завершения конкретной продажи.

Прежние журналы не сохраняли причину обычного отказа 409. Теперь диагностика операций записывает только вид операции, внутренние номера, количество принятых кадров и фиксированный код причины. Фотографии, телефоны, имена, токены, ключи запросов, файлы чеков и суммы в эти записи не включаются.

Последний срез до этой проверки: 18:22 МСК, запись №32 — 4/16 выбранных фото, №33 — 0/10, оба чека приняты. Перед итоговым отчётом после развёртывания нужен новый срез. Прямой внешний SQL закрыт настройкой сети базы; сетевую защиту ради диагностики не отключали.

## Что остаётся настройкой инфраструктуры

Не подтверждена независимая полная резервная копия базы и медиа. У базы 1 ГБ, автоматический рост и резервный узел не включены. Рабочий TURN, геозоны отелей, стандарт проверки формы и системные Web Push требуют отдельной настройки. Репозиторий публичный. Эти пункты не объявляются исправленными данным выпуском.

Для продолжения существующей продажи следует открыть её исходную очередь, заменить только явно отклонённый файл либо исправить разрешённое поле и продолжить отправку. Не очищать браузер с неотправленными фотографиями и не создавать повторную продажу вместо незавершённой.

## Результат локальной проверки окончательного кода

945 Python-тестов прошли, Ruff и проверка формата изменений успешны, все Node-регрессии прошли. Реальные изолированные браузерные сценарии подтвердили: восстановление продажи после обрыва и перезагрузки; исправление общего количества после отказа 409; замену повторного чека без потери исходных ключей и фото; медленную загрузку Академии и отклонение старого ответа; вход и график на телефоне и ноутбуке. Дополнительно проверены галереи, наборы выдачи и приватность изображений, QR/скачивание, чат и повторная отправка вложений. Проверки GitHub и рабочего сервера выполняются после фиксации этой версии отдельно.
