# Photo Boss 3.33

The owner confirmed adding hotel-zone checks and protection against arbitrary attendance photos. This release adds configurable hotel reference points and a manual-review mode; it does not claim automated face, uniform or liveness recognition.

In production, `PHOTO_BOSS_ATTENDANCE_REQUIRE_REVIEW=1` makes online arrivals and departures save private photo evidence, device coordinates, capture receipt time and hotel-zone classification as `PENDING_REVIEW`. It does not automatically approve person/uniform evidence. Time-based charges are calculated automatically, independently of that review. A different owner or scoped administrator reviews the person, uniform, location and verified time in More → Team and HR → Attendance awaiting review. The existing 500 RUB late fee uses the scheduled start (09:00 fallback without a plan). A 30-second worker records late arrival or missing arrival for scheduled shifts, plus early/missing departure when configured. More → Fines and exceptions lets owners/scoped administrators correct or waive a charge with a reason and audit. Self-adjustment is refused. Verified time recalculates the charge; an explicit monetary exception is retained across retries. Self-approval is refused. The old Telegram photo path cannot bypass protected mode; it directs staff to the app. Offline capture remains pending and is explicitly identified as device-claimed time.

The hotel comes from the day's shift plan, or a single active membership when no plan exists. Multiple hotels never silently resolve to the nearest point. Review scope still requires the day's plan for administrators; unplanned/shared days remain owner-only. An immutable per-capture context retains the point revision, distance, reported accuracy, radius and classification. Later point edits cannot change old evidence.

Inside means reported distance + accuracy is within radius; outside means distance - accuracy is beyond it; crossing the boundary is uncertain. Missing, zero or poor accuracy is always uncertain. The device can falsify GPS, so even an inside result requires review. No location is collected continuously.

More → Hotel points and zones lets owners and scoped administrators edit address, latitude, longitude and 20–1000 m radius. Concurrent edits use a revision check; all edits are audited. The Movenpick seed binds only one active hotel matching Movenpick/Мёвенпик aliases and fails closed on ambiguity. It updates that hotel's address, without creating or altering another hotel.

Production seed: Pionersky prospect 253/1, Anapa; latitude 44.979340, longitude 37.265541, initial radius 200 m. This is an initial circle around the verified map point, not a surveyed boundary. Adjust the circle after checking the actual workplace and device accuracy. A stable seed request ID prevents overwriting subsequent edits. Remove `PHOTO_BOSS_SALES_FINES_RESET_REQUEST` after the completed 3.32 reset; its immutable archive remains retained.

Still required for automatic identity/uniform verification: employee reference photos, approved uniform examples and a separately validated identity/liveness service. This release uses live camera in the normal UI and fully decodes JPEG on the server, but it does not treat the client camera path as tamper-proof evidence.

Automatic time charges use one day/kind ledger entry, adopting a matching legacy bot late-fee row rather than duplicating it. Activation begins at the local day of rollout; earlier reset history is excluded. Early/missing departure rates default to unset: events are recorded but no monetary amount is invented. The owner can set those rates; event rate snapshots preserve existing charges. Offline device timestamps do not erase an automatic late charge; verified times or a justified adjustment resolve connection-delay cases.

Completed sales now create a durable `sale_created` event in the same transaction for the owner, scoped hotel administrators, assigned manager and credited photographer. Exact replay keeps one event per recipient; role/hotel access is rechecked at delivery and inbox read. In-app polling updates the bell and shows a new-event message, even when OS push permission is unavailable. Opening a notification marks it read. System push still requires permission and a valid subscription on that device; provider acceptance alone is not a confirmed phone display.

Fixed the offline departure navigation regression detected by CI: opening shift totals is independent from whether an offline mark has already been approved.
