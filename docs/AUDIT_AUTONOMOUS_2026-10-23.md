## Сохранность данных и границы

До изменений создан Git bundle `/workspace/backups/Photo-boss-before-audit-20261023.bundle`,
а исходный коммит сохранён в GitHub-ветке `audit/backup-before-verification-20261023`.
Это резервная копия исходников, **не резервная копия production PostgreSQL или фотографий**.
Доступ к рабочей БД и независимая резервная копия хранилища не подтверждены.
Исправления проверялись во временных SQLite-базах, отдельном локальном PostgreSQL16

Реальные клиенты, смены, начисления, платежи и фотографии не создавались и не удалялись.

## Что требуется до production-приёмки

- Независимая резервная копия БД и файлов с проверкой восстановления; Git bundle недостаточен.
- Четыре отдельные тестовые роли в staging, физические Android/iPhone и Telegram.
- Проверка реальных AI/Диска, больших файлов/потери сети, закрытого телефона и второго устройства.
- Отдельное согласование недостающей автоматизации выплат/премий и произвольных скидок.
- Проверка безопасной отмены конкретной оплаченной продажи/возврата, без административного удаления истории.
- Отзыв ранее раскрытого токена из истории GitHub не подтверждён (старое предупреждение README).
- TURN в production не настроен: звонки через разные мобильные сети не приняты.
- Render MCP: list_workspaces видит My Workspace, но list_services отклонён: `no workspace selected`.
  Требуется подтверждение workspace по инструкции Render; логи/метрики/конфигурация не считались проверенными.
- Устанавливать эту ветку можно только после CI, резервного копирования и отдельного разрешения.
  `PHOTO_BOSS_WORK_HISTORY_RESET_REQUEST` при обычном выпуске должен отсутствовать.
  Это намеренно опасный механизм с отдельным requestId/scope/expectedGeneration; для аудита не включался.
