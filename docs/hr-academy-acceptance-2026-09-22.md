## Что препятствует приёмке

**Блокирует слияние этого PR:** красный обязательный CI либо обнаруженная регрессия/потеря данных. До завершения CI PR остаётся draft. Неподключённые HR-каналы сами по себе не препятствуют слиянию ручного HR. Слияние в main автоматически связано с Render autoDeploy=yes; поэтому в этой сессии его не выполнять без разрешения на выпуск.

**Блокирует production-выпуск:** новая миграция не должна применяться без свежего восстановленного бэкапа БД; нет подтверждённой копии загруженных файлов и настройки восстановления. Ролевой дефект main требует включения исправления #31 и совместной регрессии. Для полного принятия выпуска нужны реальные сценарии Android/iPhone и четырёх ролей. Зелёный build не заменяет их.

**Можно отложить с отключённой функцией:** внешняя HR-коммуникация/поиск/календарь; реальные AI/OCR; звонки через production TURN. Отсутствие каждого из этих сервисов не является блокером ручной работы HR, уроков или остальных независимых модулей. Нельзя рекламировать сквозной автоматический найм или принятые межсетевые звонки до живого доказательства.

Дополнительный эксплуатационный риск: Render PostgreSQL на free-плане имеет `expiresAt=2026-10-18T18:44:40Z`. Тариф не менялся. Требуется отдельное решение до этой даты, а не утверждение, что БД уже защищена.

## Восстановление и откат

Код проверен командой `git clone --branch main Photo-Boss-source-main-20260922.bundle restored`, затем `git fsck --full`; HEAD должен равняться указанному main. Локальная проверка сначала потребовала явного выбора main, поскольку bundle не содержит символический remote HEAD; это не повреждение архива.

Миграция добавляет nullable responsible_id, nullable reminder_at и region с пустым default. Не изменяет старые колонки, деньги или сотрудников. На откате приложения дополнительные колонки сохранять. Новые NEEDS_REVIEW-разборы в старой версии не получат кнопки пересмотра, но данные должны оставаться; нужен возврат исправленной версии или ручная административная процедура. Совместимость с реальной старой БД пока не подтверждена восстановлением.

Перед выпуском: защищённо получить свежий pg_dump PostgreSQL 16, закрытые файлы и настройки; восстановить в отдельной БД и приватном каталоге, без webhook/рассылок/фоновых внешних действий; зафиксировать количества/хэши; прогнать init_db дважды; сравнить старые данные; проверить старую версию приложения на расширенной схеме. Не хранить секреты в git и не присылать их в открытый чат.

После явного разрешения на выпуск: зафиксировать release SHA → применить штатный init_db → проверить реальный Render SHA → выполнить вход и сценарии четырёх ролей, файл с проверкой чтения, одну контролируемую продажу/кассу, практику и чат → сверить журналы/данные. В этой сессии эти действия на production не выполнялись.
