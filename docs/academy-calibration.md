# Проверка оценивания Академии на независимой выборке

Утилита `app.services.academy_calibration` сравнивает уже полученные оценки ИИ с независимыми оценками людей. Она не обращается к провайдеру, не загружает фотографии, не придумывает экспертные ответы и не подтверждает происхождение переданных меток. Сейчас в репозитории нет размеченной экспертами контрольной выборки и полученного по ней результата: точность оценивания эмпирически не измерена. Синтетические данные в автотестах проверяют только вычисления и валидацию программы.

## Как собрать выборку

1. Используйте фотографии с камеры, на использование которых в этой проверке есть необходимое разрешение. Не включайте личные данные и сведения о гостях, не нужные для анализа. Храните файлы с ограниченным доступом; в отчёт достаточно передавать обезличенный идентификатор съёмки или кадра.
2. До просмотра ответов ИИ зафиксируйте рубрику, проходной балл, определения критической ошибки, пересъёмки и случая `MANUAL_REVIEW`. Укажите версию рубрики, задачи и требований к серии. Эксперт и ИИ должны оценивать одну и ту же единицу: отдельный кадр или одну и ту же полную серию. Не сравнивайте оценку серии с оценкой одного превью.
3. Привлеките опытных фотографов. Эксперты сначала самостоятельно выставляют решение и балл, не видя оценки ИИ. При расхождении экспертов сохраните первоначальные оценки и согласуйте итоговую метку с объяснением. Не заполняйте и не «исправляйте» поле `expert` ответом ИИ: это сделает проверку круговой и недостоверной.
4. Включите разные жанры: одиночный портрет, пара, семья, ребёнок, группа. Разделите случаи по свету: открытая тень, яркое солнце, контровой, помещение, смешанный свет и вспышка. Включите хорошие работы, технический брак, пограничные случаи и сложные серии. Записывайте эти признаки как метаданные.
5. Зафиксируйте модель и её ревизию, системные инструкции, версию рубрики, разрешение изображений, доступность EXIF и параметры запроса. Не заменяйте модель или правила посреди одного отчёта. Сохраните исходные ответы и дату проверки, чтобы разбирать расхождения.
6. Разделите обучающие примеры для настройки наставника и отложенную контрольную выборку по съёмкам, а желательно и по фотографам. Соседние дубли одной сцены не должны попадать в обе части. После настройки не подбирайте контрольные метки под желаемый результат и не удаляйте неудачные случаи ради прохождения порогов.

Минимум 20 независимых размеченных работ — начальная проверка, а не статистическая гарантия точности. Для выводов по каждому жанру и свету нужны достаточные отдельные подвыборки. Общий хороший результат может скрывать ошибки на детях, группах или сложном свете. Утилита не вычисляет доверительные интервалы и сама не проверяет независимость съёмок.

## Формат входа

Вход — JSON-массив объектов. Поля одной записи:

| Поле | Требование |
| --- | --- |
| `id` | Непустая уникальная строка без пробелов по краям. Один идентификатор — одна независимая оцениваемая работа. |
| `expert.decision` | `ACCEPT`, `REVISION` или `MANUAL_REVIEW`, полученное от независимого эксперта. |
| `expert.score` | Число от 0 до 100 включительно. |
| `ai.decision` | Те же три решения в сохранённом ответе ИИ. |
| `ai.score` | Число от 0 до 100 включительно. |

Дополнительные поля, например жанр, свет, версия рубрики, ревизия модели и идентификатор эксперта, разрешены, но не участвуют в расчёте. Они не являются доказательством человеческой разметки. Булевы значения, строки вместо чисел, NaN, бесконечность, дубли `id` и повторяющиеся ключи JSON-файла отклоняются. Программа проверяет диапазон баллов, но не выводит решение из балла: критические ошибки и ручная проверка определяются зафиксированной рубрикой.

Не используйте тестовые метки как рабочую выборку. Файл реальной разметки создаётся после независимого оценивания; пример с выдуманными оценками намеренно не выдаётся за калибровку.

## Запуск

Из корня репозитория:

```bash
python -m app.services.academy_calibration /path/to/human-labelled-reviews.json
```

Пороги можно задать явно, согласовав их до проверки:

```bash
python -m app.services.academy_calibration /path/to/human-labelled-reviews.json --min-samples 40 --max-false-accept 0 --max-mae 6
```

Программный вызов: `calibration_report(records, min_samples=20, max_false_accept=0, max_mae=8)`. Функция не меняет входные записи. Минимум работ — положительное целое; допустимое число ложных приёмок — неотрицательное целое; допустимая средняя ошибка — конечное число от 0 до 100.

Коды завершения: `0` — все заданные пороги пройдены, `1` — данные корректны, но хотя бы один порог не пройден, `2` — некорректны файл, записи или параметры. Результат или описание ошибки выводится в JSON. `--help` выводит обычную справку.

## Как читать отчёт

| Поле | Значение |
| --- | --- |
| `n` | Число валидных записей. |
| `meanAbsoluteScoreError` | Средняя абсолютная разница между баллами эксперта и ИИ, в баллах шкалы 0–100. |
| `decisionAgreement` | Доля точных совпадений решений, от 0 до 1, включая совпадения `MANUAL_REVIEW`. Это не процент; `1` означает полное совпадение в этой выборке. |
| `falseAcceptCount` | ИИ принял работу (`ACCEPT`), а эксперт поставил `REVISION` или `MANUAL_REVIEW`. Неподтверждённая приёмка учитывается консервативно. |
| `falseRejectCount` | ИИ автоматически отправил на доработку (`REVISION`), а эксперт принял работу. |
| `confusionMatrix` | Строки — решение эксперта, столбцы — решение ИИ. Все девять сочетаний присутствуют, в том числе с нулевым количеством. |
| `thresholds`, `gates`, `passed` | Заданные пороги, результат каждого и итоговое прохождение. |

Если ИИ поставил `MANUAL_REVIEW` при экспертном `ACCEPT`, это передача человеку, а не автоматический отказ: случай виден в матрице и снижает совпадение решений, но не увеличивает `falseRejectCount`. Это определение нельзя менять незаметно между отчётами. При необходимости анализируйте долю ручных проверок отдельно по матрице.

По умолчанию требуется `n >= 20`, `falseAcceptCount <= 0` и `meanAbsoluteScoreError <= 8`; все условия включают границу. Пустая выборка имеет `null` вместо средней ошибки и доли совпадений и не проходит. Отображаемые средние округляются до шести знаков, но пороги сравниваются с неокруглённым значением. Доля совпадений и ложные отказы показаны для анализа и не являются отдельными автоматическими порогами в этой версии.

Нулевое число ложных приёмок в выборке не гарантирует отсутствие ошибок на новых работах. Нельзя объявлять ИИ «безошибочным» или утверждать точность по факту прохождения одних автотестов.

## Разбор расхождений и повторная проверка

Сначала вручную изучите каждую ложную приёмку и случаи с критической ошибкой, затем ложные отказы, ручные проверки и большие расхождения в баллах. Найдите конкретный кадр, наблюдаемый дефект и правило рубрики. Установите причину: спорная разметка человека, разный вход, недостаточное разрешение, отсутствующие EXIF, неоднозначная инструкция или ошибка модели. Не достраивайте отсутствующие настройки камеры по догадке.

Исправляйте обучение и инструкции на обучающей части; после изменения ревизии повторяйте проверку на отложенных работах, сохраняя предыдущие отчёты. Проверяйте отдельно жанры и условия света. При спорном или неполном входе оставляйте путь ручного разбора, не выдавая недоказанный автоматический зачёт. Даже успешно пройденная калибровка дополняет экспертный контроль и приёмку на реальных устройствах, а не заменяет их.
