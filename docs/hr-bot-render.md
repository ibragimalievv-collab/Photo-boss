# Отдельный HR-бот @Really_boss_HR_bot

## Состав

Опциональный адаптер `app/hr_bot.py` подключается к существующему Render web service
`photo-boss` после основного startup. Использует только `HR_BOT_TOKEN`, собственный
webhook `/telegram/hr/webhook`, собственный секрет проверки Telegram и собственную
таблицу черновиков `hr_bot_sessions`. Диспетчер, команды, меню, токен и webhook
основного бота не изменены. В `render_main.py` добавлен только вызов установки адаптера.
При отсутствии включения адаптер не запускается. Ошибка HR startup не останавливает
основного бота; детали исключений и токены не записываются в журнал.

Путь кандидата: /start → «Ищу работу» → согласие → имя → должность → город/регион →
опыт → телефон → готовность к работе/переезд → проверка → «Отправить анкету».
Отклик сохраняется в существующей `hr_candidates`, источник `Telegram / Really_boss_HR_bot`.
Новые права сотрудника автоматически не выдаются. HR API сохраняет существующие проверки OWNER/ADMIN.
Резюме анкеты хранится в заметке карточки. В журнале фиксируется `hr_bot_candidate_created`.
`created_by_id` — существующий активный владелец; без владельца транзакция откатывается.

Черновик переживает перезапуск; /start продолжает текущий шаг, /cancel удаляет черновик.
Одна карточка на Telegram ID, повторное подтверждение и доставка того же update не создают дублей.
PostgreSQL advisory transaction lock сериализует запросы одного кандидата.
Автоматический поиск, рассылки, звонки и фиктивные кандидаты не включены.

## Настройка Render

Сервис: https://dashboard.render.com/web/srv-damohb1mirbc73as0rl0
Workspace: My Workspace. Существующий start command: `python -m app.render_main`.
Дополнительный платный сервис не нужен. Не запускайте второй polling-процесс.

1. Проверить PR и CI; код подготовлен в отдельной ветке, production не обновлён.
2. В Environment сервиса `photo-boss` добавить **HR_BOT_TOKEN**: настоящий токен
   @Really_boss_HR_bot из BotFather. Вводить только в защищённое поле Render,
   не в чат, код, PR, .env.example или журналы. Если переменная уже существует,
   не заменять без необходимости. Не менять BOT_TOKEN.
3. Добавить **HR_BOT_ENABLED=1**. До готовности к выпуску использовать **Save only**.
4. Выпустить проверенный коммит. Существующая БД используется автоматически.
   При первом включении создаётся только дополнительная `hr_bot_sessions`
   через идемпотентный CREATE TABLE IF NOT EXISTS; прежние таблицы не переписываются.
5. Проверить `/health` и `/health/hr`: у второго ожидается `ready: true`.
   HTTP 404 означает, что адаптер выключен/не установлен; 503 — HR startup не завершился.
   Перед установкой webhook проверяется username бота. Совпадение ID с основным
   токеном блокирует создание HR-клиента. Pending updates не удаляются.
6. С реального Telegram-аккаунта пройти анкету и проверить одну новую карточку в HR
   под владельцем/администратором; для фотографа/менеджера доступ должен быть закрыт.
   Проверить перезапуск на середине анкеты и повторное подтверждение.
   Использовать реальный отклик, не заполнять рабочую базу выдуманными кандидатами.

После исправления неверного токена/сбоя HR startup требуется перезапуск сервиса.
Откат: HR_BOT_ENABLED=0 и deploy; карточки остаются, основной бот сохраняет своё поведение.
Повторная отправка ответа Telegram при сетевой неопределённости возможна, но карточка
создаётся один раз. Дедупликация между ручными карточками и другим Telegram ID не выполняется.

## Проверка и ограничения

Автоматические тесты покрывают анкету, согласие/отмену, валидацию, восстановление,
повторную доставку, откат без владельца, секрет webhook, сбой отправки и независимость
основного токена. Отдельно прогоняются существующие тесты HR-доступа и входа Mini App.
Локальные тесты используют временную SQLite, Telegram замещён mock-клиентом.
Настоящий HR_BOT_TOKEN не предоставлен через доступные инструменты: он не добавлен
и не проверен. Live Telegram, production PostgreSQL и выпуск Render не выполнены.
